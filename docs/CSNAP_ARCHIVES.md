# Windows .csnap 兼容备份

账号页的「备份格式」现在可选择「原版 Windows .csnap」。Windows 和 macOS
均能导入、导出这个格式，无需安装原版核心，也不执行上游脚本。

1. 导出：选择已有归档且当前未使用的 A–D 槽位，选择一个新的 `.csnap` 文件，
   输入至少 8 位的密码并确认。成功前会重新解密并比对全部文件。
2. 导入：选择原 `.csnap`，填写原密码，选择存档原来的 A–D 槽位。槽位必须为空、
   未使用且没有待恢复事务。旧存档的短密码和小写账号标记可以导入。
3. 需要其他槽位名、重命名槽位导入，或资料中有格式保留名称时，使用 `.envsnap`。
   macOS 的 `.dmg` 选项继续保留。

选错槽位、密码不对、文件损坏、路径不安全或已有资料时，显示具体原因并停止。
不覆盖已有文件，不启动 Claude，不主动登出、登入或修改账号身份。密码输入框在提交后
清空，密码不写入日志、参数列表或恢复记录。请单独保管密码；丢失后没有恢复后门。

## 已核对的格式

来源是 claude-switcher 的
[`a45cede` Windows 实现](https://github.com/YOURSJEYO/claude-switcher/blob/a45cede34042922f881ef9672148cc7c8ddccff1/windows/claude-switch.ps1#L1864)。
这是独立的 `CSNAP001` 读写实现；现有 `ENVSNAP1` 并未冒充上游格式。

| 字段 | 协议 |
| --- | --- |
| 头部 | `CSNAP001` 8 字节、salt 16、IV 16、HMAC 32，共 72 字节 |
| 密钥 | UTF-8 密码，PBKDF2-HMAC-SHA256，200000 次，64 字节；前后 32 字节分别用于 AES 和 HMAC |
| 加密 | AES-256-CBC，PKCS7 填充 |
| 认证 | HMAC-SHA256，覆盖头部前 40 字节及全部密文；常量时间比较，成功后才创建明文 |
| 内容 | 无外层文件夹的 ZIP，支持 stored / deflate 与 ZIP64 |
| 标记 | 根目录 `.claude-switcher-snapshot.json`，最多 16 KiB；格式、整数版本 1、账号 A–D 与目标槽位相同 |
| 密码 | 导出至少 8 个 UTF-16 单元，与原 Windows 输入长度一致；导入任意非空原密码，最大 1024 单元 |

旧存档无需额外的 EnvScope 清单。整份 ZIP 由 HMAC 认证，ZIP 内容另做 CRC 检查，
最终复制由 AccountManager 比对。新导出会完整回读比对，而不是只检查文件存在。

## 实现边界与验证

- 密文先复制到当前用户专用的暂存目录。验签失败不创建明文；解密的第二次读取
  也重新验证 MAC 与文件身份，读取期间变化会停止。
- ZIP 先检查中央目录大小，再加载条目。最大明文 ZIP / 展开内容各 8 GiB，
  最多 200000 个资料项，中央目录最多 64 MiB；超限明确拒绝，不静默遗漏。
- 拒绝绝对路径、盘符、反斜线、目录穿越、设备名称、特殊文件、重解析点、
  硬链接源文件，以及大小写 / Unicode 名称与文件目录冲突。跨平台不安全名称
  会拒绝；可改用 `.envsnap` 保留原资料。
- 导出目标须在管理目录外，使用同目录暂存和不覆盖的原子发布。并发创建的同名文件保留。
- 初次检查与最终导入分别持有账号锁；期间出现占用或 `.new/.previous` 事务时停止，
  原有待恢复资料保留。既有账号恢复入口仍是唯一恢复路径。
- 自编 .NET AES / PBKDF2 / HMAC 程序生成 6 个固定向量，覆盖空数据、整块、
  非整块与含中文 / 非 BMP 字符的密码；Python 逐字节匹配。独立 .NET `ZipArchive`
  与 Python 实际双向交换在 Windows 执行；所有系统运行相同向量和模拟事务测试。
- 三个桌面包的隔离窗口验收包含 `.csnap` 导入、导出及暂存清理，证据字段为
  `native_csnap_roundtrip`。不执行上游代码，不读取真实用户资料。

存档保存本机资料，不包含系统钥匙串。复制成功不能证明跨机 OAuth 凭据仍有效，
也不能证明服务端把账号视为某台恒定设备。实际登录有效性仍由官方客户端确认。
