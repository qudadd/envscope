# 新用户使用指南

[项目首页](../README.md) · [文档目录](README.md) · [下载 0.25.0 Alpha](https://github.com/qudadd/envscope/releases/tag/v0.25.0-alpha.1)

EnvScope 帮你看清 Claude 的本机环境问题，执行已确认的修复，并按需持续检查。它不提供账号、代理节点或订阅；账号实际能否使用，最后仍要在自己的 Claude 中确认。

## 1. 打开软件，确认目标

完整解压与你的系统和处理器对应的软件包，打开 `EnvScope.exe` 或 `EnvScope.app`。独立包自带运行环境，无需终端。当前包的签名状态见 [下载说明](../README.md#下载与启动)。

首次打开有使用教学，可以跳过，也可从左下角“使用教学”重看。完成教学不会修改系统配置或启用守护。

首页“地区与时区”中：

- 填写**实际使用地区**，再确认用途与连接方式；不确定用途时可选择自动识别。
- 读取出口 IP，获得**节点国家与城市建议**。列表按对应国家提供代表城市，并填入目标时区、地区格式与语言。
- 其他城市可选择同一时区的代表城市，或使用自定义目标。查询失败时可手动填写，不会把本机当前值自动当成正确目标。

实际所在地与出口分开记录。地区预设只是配置选项，不代表 Claude 官方支持全部地区。时区与语言差异本身不用于推断账号封禁概率。

## 2. 一键检测，看清问题

点击“确认并一键检测”。首页显示本次目标、已完成的必需检查、问题与下一步。需要深入查看时，打开具体问题或“全部检查与证据”。

| 结果 | 含义 | 接下来怎么做 |
|---|---|---|
| 所列范围通过 | 当前证据满足这一项的检查条件 | 继续处理其他必需项 |
| 不合格 / 发现问题 | 测到了与目标不符或影响使用的情况 | 查看修复方案，或按手动步骤处理 |
| 需要授权 | 系统明确拒绝了这一项需要的访问 | 查看读取用途，按入口授权后返回复检 |
| 超时 / 缺少证据 | 本次未取得足够信息，不能确认好坏 | 查看原因、检查连接后重测 |
| 本版未支持 | 软件尚无对应测量能力 | 阅读边界，更多权限不能补齐这一项 |
| 不适用 / 未选择 | 当前用途不需要，或本次没有测 | 不计入通过；缺少必需项时整体仍待完成 |

环境结论仅覆盖所列条件。系统配置存在不证明实际进程流量；HTTP 有响应不证明账号可用；原生 UDP 观测不等于浏览器 WebRTC。展开证据可看到测量来源、时间与范围。

想只检查部分项目时，进入“更多功能 → 全部检查”。可以单选、全选、只选需处理项或选择筛选结果。未选项不会沿用旧结果；启动或切换账号的必要复检不会因此跳过。详见 [选择检查](SELECTIVE_CHECKS.md)。

## 3. 按项授权，修复并复检

软件先生成只读方案，列出要改什么、影响什么、能否撤销。核对后点击确认才执行。需要先启动代理客户端时，会先完成该步骤并复检，再按新结果生成后续方案。

授权与修复的区别：

- **读取权限**：只为对应失败项提供入口。打开系统设置不等于已授权，返回后实际复检；拒绝或取消会保留原因。
- **系统修改权限**：更改时区、IPv6 或安装系统守护时，可能由系统请求管理员授权。EnvScope 不接收或保存管理员密码。
- **组织策略限制**：不能通过反复点击授权解决，需由管理这台电脑的人处理。

支持自动处理的配置先保存原值与恢复记录，再执行和读回。遇到不支持的修复会标明原因与手动步骤。DNS 缓存刷新不可恢复原缓存，会单独说明；不要把所有操作都理解为可撤销。

修复结束后自动复检，分别列出已消除、仍存在及证据不足的问题。方案过期、目标变化或文件后来被修改时，不会继续使用旧方案覆盖新设置。部分完成或中断的操作，先处理恢复入口，再发起新修改。

Code 配置只改用户文件中已审核的字段，保留其他设置。项目或组织配置仍可能覆盖它，修改后应重开终端或会话。配置备份保存在本机，**未加密、可能含密钥，不可上传分享**。更多说明见 [检测与处理](DIAGNOSIS.md)。

## 4. 确认实际使用，再开启守护

检测与修复后，回到自己的 Claude 登录并发一条消息。首页“详细记录与使用帮助”保留打开 / 正常重开桌面版的入口，操作前重新核对必要条件；Code 用户需重开自己的会话。

“我已收到 Claude 的回复”仅记录你的本次手动确认，不改变技术报告，也不成为下一轮的自动通过证据。匿名 API 的 401 只表明到达认证边界，不等于密钥错误或登录成功。

需要长期保持时，在首页“持久化守护”或侧栏“持续守护”中选择范围，预览并确认：

| 功能 | 运行方式与限制 |
|---|---|
| 定时巡检 | 默认关闭，可选 5 / 15 / 60 分钟；显示实际完成时间和失败原因 |
| 配置与代理保持 | 仅恢复批准的字段、节点与所选客户端；保留日志，反复失败暂停 |
| 系统时区服务 | Windows / macOS 可在前台申请相应系统授权，按批准时区每 60 秒检查；单独提供停用与恢复入口 |
| 进程守护 | 另行审核的 10 秒监测；触发条件时可能停止已识别 Claude，需先保存工作，不等于防火墙断网 |

后台不会反复弹出授权框。权限不足、心跳过期、旧任务冲突或恢复受阻时，会保留异常与处理入口。更改目标或代理后重新检测并审核新的守护方案。[Watchdog](WATCHDOG_AND_IDENTITIES.md) · [系统时区守护](TIMEZONE_SERVICE.md)

关闭窗口默认驻留托盘 / 菜单栏，可从菜单重新打开或退出；“设置 → 软件与后台”可关闭驻留。**退出应用不会自动删除已批准的系统任务**。停用普通巡检和移除独立系统时区服务是各自的操作，按对应入口处理。

## 多账号与备份怎样使用

只有一个账号时，直接在 Claude 登录，无需建槽位。账号页管理 Claude **桌面版的本地资料**，不负责注册、订阅或密码管理；浏览器和 Code 的登录不会跟随切换。

1. 给 A 命名并检测启动条件，保存桌面应用中的工作后，将当前资料归档到 A。
2. 给另一个槽位命名，使用“首次登录”，在 Claude 中自行登录另一个账号。
3. 以后使用“切换并打开”。软件重新检测、正常退出应用、校验封存与载入；不会通过调用登出来切换。
4. 发现未完成事务时，先审核恢复方案。所有现场副本保留，不要再用另一套工具同时交换资料。

本地资料独立不保证系统钥匙串、DPAPI、跨设备会话或服务端设备判断完全一致。优先使用 `.envsnap` 加密备份；高级目录导出未加密，包含敏感资料。密码不由软件保存，遗失后无法代为恢复。[账号资料与恢复](ACCOUNT_VOLUMES.md) · [加密格式](CSNAP_ARCHIVES.md)

## 更新、日志与反馈

“设置 → 软件与后台”默认每日向 GitHub 查询版本；下载、安装和重启需要确认。更新核对仓库、架构、摘要和应用身份，保留前一版本用于回退。已启用的任务仍引用原来批准的程序路径，移动应用后需重新核对。[更新说明](OPEN_SOURCE_BUILDS.md)

“更多功能”中可以查看历史、工具和环境信息。分享问题时附上系统、软件版本、操作步骤和复核过的脱敏诊断包，不要上传账号卷、配置原文、真实 IP 或代理凭据。

只有通过源码的浏览器兼容模式运行时，才需要留意本地页面端口：服务退出后旧页面失效，重新启动并使用新打开的页面即可。独立软件日常使用无需记住端口。

## 与其他开源工具怎样配合

| 工具 | 实际作用 |
|---|---|
| [claude-switcher](https://github.com/YOURSJEYO/claude-switcher) | 功能参考、固定源码与明确的维护兼容入口；上游输出不直接变成本项目通过结论 |
| [Mihomo](https://wiki.metacubex.one/api/) | 通过已有本机控制接口读取状态；经确认可选择已有节点并验证，不创建节点 |
| [Clash Verge Rev](https://github.com/clash-verge-rev/clash-verge-rev) | 可选外部客户端，提供相应的启动、TUN 与路由维护；需单独安装 |

更多平台差异见 [完整功能对照](FULL_PARITY_AUDIT.md)。Scrapling 只用于开发研究，第三方许可见 [来源说明](../THIRD_PARTY_NOTICES.md)。
