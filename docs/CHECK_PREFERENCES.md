# 可选检测、FlClash 与脱敏诊断

0.21 的独立功能增量，面向 Windows / macOS；整体上游功能升级仍以
[完整核对表](FULL_PARITY_AUDIT.md) 为准。

## 使用入口

在「设置 → 检测偏好」选择出口变化、DNS 配置 / 权威出口、UDP / WebRTC、客户端语言、
ASN 和外围服务连接。保存到本机私有设置；一键检测与后台巡检共用。已有确认目标时，
检测策略变化后自动复检。「全部检查」可以全选或单独测量；明确选择的本轮项目可以
临时覆盖保存的跳过偏好。未选、超时、未知都不会变成通过。

所选目标的必需检查与依赖保留，例如严格 TUN 保护所需的原生 UDP，或明确指定的
Claude 应用语言。官方实际使用地区、认证、证书与目标选路不能通过可选开关取消。
DNS 解析仍用于目标连接；关闭可选 DNS 项不会关闭必需的域名解析。

「允许非必需补充检查的失败或告警」只影响固定白名单内的补充项目；原始状态不变。
外围连接不全、出口变化可以保留记录后继续基础使用验收。证书明确失败、地址策略
违反和目标必需检查不能因此放行；完整隐私判断继续使用独立的严格判定。
未知证据不会被填成通过，基础使用结论始终只覆盖所选目标。

外围检查匿名请求 10 个固定端点的 HTTPS 头，不使用账号、Cookie 或 API 密钥；使用
已选择的传输路径，不因失败重试直连。收到经证书校验的 HTTP 响应只证明该端点回应，
403 / 404 不证明登录、支付或验证码功能可用。证书失败单独保留。

## FlClash

目标配置、设置、安装识别、启动 / 正常重开 / 恢复、代理离线重开与进程守护均识别
FlClash。内核条件检查 `FlClashCore`，不会只因为 GUI 存在就宣告内核在线。
一键流程可以先启动离线客户端，自动复检后再审核实际出现的网卡与后续保护。

FlClash 的 TUN 与规则配置仍需在原客户端中完成，界面标红并给出手动步骤。
它使用自己的偏好存储，不能把 Clash Verge 的 `enable_tun_mode` 写到它的目录。
现有自动修改只适用于已验证的 Clash Verge 配置；启动请求不等于 TUN 或服务已可用。
程序更新后需要重新审核摘要；本次开发测试没有启动实际安装的代理软件。

接口来源为 [FlClash AppPath](https://github.com/chen08209/FlClash/blob/7fd417fb9a9a277c6a9339a8ac87f907df7c25f7/lib/common/path.dart)、
[偏好接口](https://github.com/chen08209/FlClash/blob/7fd417fb9a9a277c6a9339a8ac87f907df7c25f7/lib/common/preferences.dart) 与
[Windows 包装定义](https://github.com/chen08209/FlClash/blob/7fd417fb9a9a277c6a9339a8ac87f907df7c25f7/windows/packaging/exe/inno_setup.iss)。

## 日志与 ZIP

命令日志默认开启，可以关闭或单独清除。每份上限 512 KiB，仅保留当前和上一次轮转
两份。记录时间、固定命令名、固定状态和耗时；参数、账号、路径、IP、异常原文、
输出与凭据不进入日志。关闭时不新增记录，导出也不包含旧命令日志。此开关独立于
修复备份、事务记录和守护留痕；仅改变日志开关不使现有守护基线失效。

「导出脱敏诊断 ZIP」在桌面弹出系统保存对话框，在浏览器兼容窗口触发下载。
固定白名单包含 `summary.json`、`commands.jsonl` 和说明文件。只保留检查名称 / 状态、
严格验证的检测偏好与命令元数据；不遍历应用目录、不复制原始报告、账号数据卷、
代理配置、历史报告或修复备份。即使本地日志被加入任意字段，也重新构建允许字段，
不会直接打包原文件。时间与命令仍可能透露使用习惯，分享前应自行复核。

## 验证范围

单元回归覆盖必需依赖、实际探测跳过、单次覆盖、告警不阻断的明确例外、证书失败、
跨重启保存、后台配置一致、日志关闭、轮转、并发写入、敏感字段污染、硬链接拒绝、
导出取消和保存。离线 UI 覆盖 Windows / macOS 的 1024 / 1440 宽度、自动复检、全选、
ZIP 下载、刷新后偏好恢复，以及 FlClash 手动 TUN 提示。冻结包另验证模块导入、
持久日志同意与 ZIP 内容；没有将模拟结果当作实际代理 GUI / VPN 驱动验收。
