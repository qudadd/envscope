# 原生进程守护（0.13 开发版）

在持续维护中单独生成并批准方案。全面巡检与修复按分钟运行，进程守护单独以
10 秒周期运行，不依赖原版维护核心，也不随网页或主窗口关闭而停止。

HTTP 模式监测检测目标中明确填写的本机无凭据 HTTP / HTTPS 端口。TUN 模式由用户
选择确切的网卡，监测该网卡是否在线，并按客户端模式检查已知内核进程；auto / other
仅检查指定网卡。它们是组件存活条件，不证明实际流量走向、出口国家或服务可用。
真实代理故障演练、第三方客户端各版本的适配和睡眠恢复仍需独立验收。

组件离线或读取失败时，只对能够验证为当前用户、已知安装目录的 Claude 桌面进程
采取停止操作。Code、其他用户进程、任意同名程序和无法读取身份的进程不会被误当成
可停止目标。每次信号前检查创建时间和路径；psutil 的信号接口另检查 PID 复用。
先发送终止请求，2 秒仍在运行则强制结束，再检查是否确实退出。未保存内容可能丢失。
无法确认身份或停止失败会标红并要求手动关闭，不声称已停止。

收到新心跳、进程 PID / 创建时间 / 可执行文件仍对应、系统任务归属符合方案，才判定
该守护正在运行。30 秒以上无有效心跳、工作进程退出、任务变化或检测目标改变，
不会继续给出守护通过结论。后台工作进程使用独占锁；停用先写入禁用状态，再移除
系统任务，任务移除失败也不能继续执行新的停止动作。

Windows 使用当前用户的 `EnvScopeProcessGuard` 计划任务；macOS 使用
`org.envscope.process-guard` LaunchAgent。它们与全面巡检任务分开，不提权。
每次登录启动，异常退出后最多等 5 分钟再次调度；停用后保留日志。日志按日追加在
`~/.envscope/process-guard/events/`，最近记录缓存轮替不删除完整文件。

本功能存在轮询和终止时间窗口，不是防火墙、WFP 或 pf。睡眠期间无法巡检；
守护不能防止周期内发送的数据包，不保证账号可用，也不改变官方地区要求。

验证：`tests/test_process_guard.py` 覆盖审批、基线变化、心跳、端口 / 网卡 / 内核
故障、停止失败、PID 复用、独占和停用。实际 psutil 停止测试只操作测试自己创建的
Python 子进程，并先验证普通 Python 不属于产品可停止范围。Windows / Darwin
界面流程使用注入适配器；真实 Claude 进程未操作。冻结包检查新工作入口、依赖和控件；
CI 调度验收对维护与进程守护任务分别等待两次自动 `--check-runtime` 执行及移除，
该检查不等同于真实代理掉线后的完整保护验收。

依据：[psutil 官方接口](https://psutil.readthedocs.io/)、
[上游进程守护](https://github.com/YOURSJEYO/claude-switcher/tree/223a5cc44edf36dfa568903ab02e73f0f015ec9e/daemons)。
