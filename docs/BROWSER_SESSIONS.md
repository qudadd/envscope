# 临时浏览器资料与独立清理

“工具 → 临时浏览器”使用新的资料目录，不带入日常浏览器 Cookie、扩展或登录状态。
打开前仍须通过目标环境检查。打开时一次确认，也授权会话关闭后的清理；不伪装设备、
时区、语言或所在地。浏览器 UDP 选项不等于防火墙隔离，仍需在临时窗口复查 WebRTC。

新会话保存本机恢复记录，并启动独立的隐藏清理进程。主窗口关闭或应用退出后，清理
进程继续检查；会话结束且完成清理后自行退出。重新打开独立应用时，也会恢复此前
已授权会话的清理。正常窗口内的清理线程继续保留，独立进程失败时可手动重试。

工具页列出会话数、待重试、旧版和无法核实的数量。后台状态分别核对实际进程身份、
命令范围及心跳；“已请求启动”不冒充“进程已验证”。记录读取失败或心跳过期明确提示。

“清理已关闭的临时浏览器资料”会先说明影响并要求确认，可处理旧版平铺目录和启动
期间中断的记录。正在使用、无法确认退出、记录损坏、目录归属不明时保留。若始终
保留，先退出临时浏览器所有窗口，再重试；可点“临时资料目录”检查具体会话，或点
“清理记录”查看原因。不要清理日常浏览器目录。

## 范围与保护

- 资料位于当前用户的 `.envscope/browser-sessions/<随机代号>/profile`；会话记录
  保存在相邻的 `session.private.json`。新目录先限制读取权限，再启动浏览器。
- 工作进程只处理已授权的有效记录。旧版无记录目录只有在手动确认后才进入清理。
- 清理前核对启动进程的 PID 与创建时间，避免进程号复用；再两次检查是否仍有进程
  使用该资料。无法读取相关进程时保留。早于随机目录创建、且参数无法读取的无关
  旧进程不阻塞该新会话；未来或异常时间戳不会据此放行。
- 进程参数是观测范围，不是对第三方浏览器内部状态的完全证明。受保护进程、异常
  浏览器版本或损坏记录可能仍需要人工核实；不强行终止任何真实浏览器。
- 清理只进入固定根目录下的已核实会话；链接根目录、共享记录、重复 JSON 字段、
  归属异常与额外文件会停止处理。中断后保留记录，下一次可重试。
- 状态读取不创建目录或锁。手动清理、启动、独立工作进程使用操作锁，避免相互覆盖。
  单轮最多检查 256 个目录，超限明确提示，不宣称全部清完。
- 清理日志只记录时间、随机会话代号和状态，不记录链接、代理、Cookie 或登录内容。
  它不属于诊断 ZIP 的导出白名单。

开发与验收使用模拟 Cookie、专用临时目录、注入进程状态，以及真实的无害睡眠进程。
Windows 与 macOS 冻结包另验证父进程先退出、工作进程继续运行、观测到无害进程结束、
资料移除及工作进程自行停止。不会运行 vendor 清理脚本或启动真实 Chrome / Edge。
标准隔离窗口先报告测试入口能力，确认后才调用专用临时目录入口，避免向旧版程序
发送未知参数而意外启动正常应用。
