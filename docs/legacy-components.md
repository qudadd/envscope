# 旧后台任务迁移

在“持续维护 → 旧后台任务迁移”读取旧任务。可识别的任务默认选中，可单项选择或全选；先预览，再确认停用。执行时需要的管理员权限由 Windows / macOS 系统申请。

当前原生范围：

| 平台 | 任务 |
| --- | --- |
| Windows | 当前用户的 `ClaudeBodyguard` 计划任务 |
| macOS | 系统 `local.claude-bodyguard`、`local.tz-watchdog`、旧版系统 `local.claude-update`，以及当前用户的 `local.claude-update` LaunchAgent |

程序先核对命令、任务用户、定义、原脚本摘要和文件权限，保存受保护的原值及事务记录，再停止、移除登记并独立读回。未知命令、同名外部任务、权限拒绝或确认前发生的变化都会阻止操作。未登记、暂停、禁用、运行四种状态分别保存。

本操作保留账号、凭据、原脚本和旧界面，**不等于完整卸载**。执行前请退出旧界面和手动启动的旧脚本；不会按进程名称批量结束它们。移除旧登记后有保护间隔，自动复检后仍需审核 EnvScope 原生守护，收到新心跳才显示正常。

“预览恢复原任务”恢复整笔已保存事务。先停用对应 EnvScope 守护，防止两个配置基线同时工作。原来未登记或暂停的任务保持原状态；原来已经登记的任务恢复后，`RunAtLoad`、登录或定时条件可能立即执行原脚本。脚本已改变或出现不同的同名任务时，停止恢复并保留副本。未恢复的事务不会被后续迁移覆盖；需要改变范围时，先恢复再重新选择。

原生进程守护会在预览、确认、后台巡检和状态核对时读取旧守护；旧登记重新出现或读取失败时，暂停自身自动停止并记录原因。macOS 系统时区守护也会在每轮写入前检查旧任务，冲突时暂停修改。旧版工作进程的心跳不能证明新策略已经生效，升级后需要重新审核。

桌面一键修复遇到待修复的旧守护时，会先预览旧任务迁移，确认并复检后再生成客户端和原生守护方案。后续接口以新检测为准，不提前批准尚未建立的隧道。只勾选进程守护时，迁移范围限制为对应的旧进程守护。

Windows 任务计划程序可能将“允许访问”项重新排列，并补充自动继承标记。读回比较保留原用户、组、访问掩码、继承属性和继承保护，只接受全部为普通允许项时的等价排列；拒绝或特殊访问规则转为手动处理，不在移除后试着猜测其意义。

开发验证使用临时文件、回环 HTTP 和 CI 中唯一命名的无害任务，不运行 vendor 脚本，不改变真实代理、时区、账号或 Claude。Windows UAC 弹窗和 macOS 管理员交互仍需在实际授权操作中由用户完成，CI 不将已提升权限等同于验证了授权界面。
