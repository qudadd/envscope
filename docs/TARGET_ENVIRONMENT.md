# 目标环境与验收（0.9.0 Alpha）

首次打开先确认目标，之后直接点击检测。确认只保存 EnvScope 的本机偏好；修改系统或应用配置仍需审核具体方案。

| 目标 | 默认处理 | 检查范围 |
| --- | --- | --- |
| 网页、桌面、Code、桌面与 Code | 读取安装情况给出建议，由用户确认 | 只用相关安装、配置和端点判断合格 |
| 直连、HTTP / 系统代理、TUN / VPN | 读取已有连接给出建议，由用户确认 | 探测路径、应用代理配置；TUN 还检查目标地址选路 |
| 时区、地区格式 | 建议保留当前电脑值；留空仅记录 | 比较明确目标；时钟准确性另用多个 HTTPS 日期检查 |
| Code 提供方和认证 | 默认保留官方接口与现有登录 | 配置是否一致；不读取或发送密钥，不冒充登录验证 |
| 出口国家、桌面应用语言 | 默认不设限制 | 填写目标后才加入验收；桌面偏好不替代网页或 Code 的语言 |
| IPv6 | 默认仅观察 | 可明确要求关闭或出口在允许网段；无响应不能证明关闭 |
| 保护要求 | 标准使用条件 | 严格模式额外检查 TUN、UDP、IPv6、所选守护和运行规则 |

首页明确列出必需项的通过、不合格和待完成数量。“全部检查”把必需项放在前面，可筛选目标验收或本次必需；原有 14 类基础、18 类扩展和独立测量全部保留。不适用于所选用途的故障不阻止基本使用验收，但原始结果不会被改成通过。

未知的原因分开处理：系统明确拒绝读取时提供对应授权入口；探测失败显示实际错误；尚未实现的权威 DNS 出口和进程全流量关联保留未验证。没有权限拒绝证据时不建议盲目提升权限。403 仍需实际应用访问校验，405 不作为服务正常的证据。

## 配置与长期保持

- HTTP 模式：核对目标代理，验证无认证 Models API 的 GET / TLS 响应后，才在确认方案中写入 Code 用户配置。
- 直连 / TUN：可移除 Code 用户配置中冲突的 HTTP(S)_PROXY、ALL_PROXY 大小写字段，恢复 TLS 校验；不会改写终端或系统环境变量。若仍继承代理，明确提示来源需要处理，复检不会假装已修复。
- JSON 的可确定多余逗号可修复。原文件备份、并发修改拒绝覆盖、逐字节撤销和复检继续生效；MCP、权限及其他字段保留。
- 自定义 / 云提供方保留既有接口和凭据，其实际认证端点没有自动探测时明确列为待完成；不使用官方 API 的响应冒充该提供方成功。
- 时区、地区、语言、客户端安装、云认证和网络服务权限按具体问题引导处理。本版不把“保存检测目标”声称为“已更改操作系统”。
- 目标修改后清除本机旧报告，拒绝旧修复方案；后台配置恢复也受目标指纹约束。重新检测后可重建维护方案。
- 标准目标的桌面启动使用对应使用条件；严格 TUN 目标保留额外保护门槛。每次启动或交换账号前仍由服务端重新检测，并检查账号事务完整性。

## 可复现的模拟测试

这些是自动化夹具结果，不是用户真实 Claude 账号或网络通过证明。所有外网响应、系统资料和代理测试由夹具提供，文件操作仅发生在临时目录，不执行上游脚本。

1. `python -m unittest discover -s tests -p test_target_environment.py -v`：Windows/macOS × 四种用途 × 三种连接方式，共 24 个正常组合；两系统各 13 种故障，共 26 个故障组合；另测网页 403、桌面缺失、守护未运行、IPv6 目标冲突、云接口未验证、认证缺失与 TUN 物理选路等边界。
2. 三种连接方式分别执行真实的临时配置预览、确认、写入、复检与逐字节回退；测试保留私有字段、目标改变拒绝旧方案、继承代理不被改写。
3. `python -m scripts.target_environment_smoke`：1024、1280、1440 像素桌面窗口；验证首次确认门槛（含服务端）、保留时区地区、修复复检、重开后免重复设置、取消不保存、切换到网页后不改 Code、完整记录不冒充隐私通过。
4. 原有浏览器、使用性、桌面设置、账号临时资料往返、维护恢复与更新确认测试继续执行。结果和截图在被 Git 排除的 `artifacts/` 中。

真实登录、订阅和模型权限仍需在用户自己的 Claude 中确认回复。模拟 macOS 系统资料不替代真实 macOS GUI、权限对话框和长期休眠唤醒测试。
