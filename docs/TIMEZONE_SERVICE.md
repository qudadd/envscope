# Windows / macOS 系统时区守护

先填写实际使用地区和期望城市，完成一次当前目标的检测。在“保持本次设置”勾选
时区守护并预览，所需系统授权会合并在同一份方案中。也可在“持续维护”的系统
时区守护入口独立安装或更新。普通检测不会安装服务，应用不接收或保存管理员密码。

确认后按需申请系统授权，此改动影响整台电脑。完整独立桌面包随附编译好的辅助程序；
源码安装缺少该程序时会给出获取完整包的提示。Windows 先检查当前用户令牌，具备时区
权限时使用原用户任务；缺少权限时将系统任务授权纳入同一份守护方案。

Windows 系统任务 `EnvScope-TimezoneGuard` 使用 SYSTEM 身份，每 60 秒运行固定的原生
`timezone-helper.exe --once`。固定目录为 `%ProgramData%/EnvScope/TimezoneGuard`，
只允许 SYSTEM 与管理员写入；普通用户可读状态及任务定义。前台安装脚本是可读的固定源码，
提权入口核对一次内存快照的摘要后执行；不会降低执行策略，也不会把可写脚本交给后台任务。
辅助程序执行前核对路径、所有者、ACL 与自身摘要，仅在写时区期间启用所需令牌权限。
事务日志为 `lifecycle-YYYY-MM-DD.jsonl`，周期事件为 `events-YYYY-MM-DD.jsonl`。

## 自动处理和撤销

- 原生 Windows 任务 / macOS LaunchDaemon 每 60 秒读回时区；有漂移时记录原值和目标，调用系统时区接口，
  再独立读回。启动安装时的一次读回不算周期巡检成功，界面等待新心跳。
- 尝试至少相隔 5 分钟，24 小时最多 3 次；调用超过 20 秒会停止等待并记录。
  未完成写入、反复失败或系统时间异常不会计为守护正常。
- 在“地区配置”更换目标时，同步更新已安装服务的基线。撤销同时恢复旧服务文件、
  尝试记录和修改前时区，避免旧基线再次覆盖新目标。
- 新增系统服务后，若用户巡检任务注册失败，按已披露方案撤销本次系统服务操作。
  若取消补偿授权或回读不完整，保留红色状态和恢复入口。
- “预览撤销上次操作”只使用最新事务的受保护备份；系统时区、服务或辅助程序在
  预览后改变时停止。支持撤销安装、更新或移除。进程中断先恢复未完成操作。
- 移除可选择恢复首次安装前时区。停止用户巡检不会连带移除单独授权的系统服务，
  需在系统服务入口审核停用。备份和日志保留在本机。

## 权限和文件

以下固定服务路径说明适用于 macOS。当前最低版本保留 macOS 12，因此仍使用受保护
LaunchDaemon；[SMAppService](https://developer.apple.com/documentation/servicemanagement/smappservice)
适用于 macOS 13 及以上，后续迁移需一并验证批准状态和旧服务移除，不能仅替换注册调用。

辅助程序是独立 C 程序，只链接系统库和 CoreFoundation；不以 root 运行 Python、
PyInstaller 入口、用户可写脚本或上游代码。打包时以压缩数据载荷保留辅助程序的原始
字节，避免打包器重签名改变摘要；先在普通用户的私有临时缓存解包并校验。每次前台
授权再将辅助程序复制到
root 持有的暂存目录，核对 SHA256 后执行。没有 setuid、无网络端口和通用命令 RPC。
系统任务只调用固定的辅助程序入口和系统时区接口。

固定路径：

- 服务：`/Library/LaunchDaemons/io.qudadd.envscope.timezone.plist`
- 辅助程序、基线和备份：`/Library/PrivilegedHelperTools/io.qudadd.envscope.timezone/`
- 每日检查日志：该目录下的 `events-YYYY-MM-DD.private.jsonl`
- 生命周期日志：该目录下的 `install-events.private.jsonl`

基线和公开心跳只包含系统时区、版本、时间戳、状态等信息；备份与待恢复现场
由 root 持有，普通用户不能覆盖。系统服务与前台生命周期均使用独占锁。
日志属于本机操作记录，不是防篡改审计；长期运行需要自行归档。

原版 `local.tz-watchdog` 正在运行时，新安装会被阻止并标红。当前不自动修改旧核心。
确认已不需要原版时区守护后，可在终端逐行执行以下固定命令，由 macOS 请求授权：

```sh
sudo launchctl disable system/local.tz-watchdog
sudo launchctl bootout system/local.tz-watchdog
```

第一行停用后续加载，第二行停止当前任务；“service not found”表示当前未注册。
原版文件与账号存档均保留。刷新 EnvScope 后再预览新服务。如需恢复原任务，先移除
EnvScope 系统时区服务，再执行 `sudo launchctl enable system/local.tz-watchdog` 并按原版
安装方式加载。管理员策略不允许时，请由管理员处理。

## 已验证范围

单元和界面测试使用注入的系统状态。Mac Intel 与 Apple 芯片 CI 另外编译只作用于
唯一临时路径的辅助程序，通过真实 root LaunchDaemon 验证安装、至少两次自动运行、
漂移恢复、更新、失败回滚、中断恢复、已提交事务撤销和移除。测试前后核对真实
`/etc/localtime` 不变，最后删除本次临时任务和目录。临时辅助程序不会进入发布包。
冻结包另行核对生产辅助程序版本、摘要和 `fixture=false`；结果以对应发布 CI 为准。

真实用户授权弹窗、用户设备的睡眠唤醒和 macOS 自动时区竞争尚未完成设备验收。
系统自动时区反复改写时会触发限流并标红，需要用户在系统设置核对策略。
修改时区不能改变实际所在地或官方地区资格，也不能保证服务端账号可用。
