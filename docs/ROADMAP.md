# 实施路线

## 0.7：从修复到桌面使用

已实现：首页复检后打开、确认正常退出后再次复检并重开；安装、桌面 JSON、账号资料、
独立网页端点及原有连接条件合并为可读清单。API 回应不代替桌面访问，访问校验不算登录。
同账号操作锁、严格确认、恢复副本保留；Code 范围隐藏桌面入口。
真实 OS 调度生命周期纳入三架构冻结包 CI：注册、两次自动运行、移除。
实际登录、睡眠恢复与 Safari 仍保留独立验收边界。见 [交付验收](PRODUCT_ACCEPTANCE.md)。

## 0.6：一条龙配置与修复

已实现：检测后自动合并方案；Code 主动配置完善；优先现有本机代理与显式选路；写入前
二次验证；自定义/云平台路由保护；继承环境变更与方案过期拒绝；不为格式化重写相同值；
复检配置文件凭据；首页长期保持预览、启停；操作期间防止选项及并发请求混淆。
配置文件符合方案不代表实际进程采用配置，仍需重开和实际回复确认。

## 0.4：逐项核对与持续维护

已实现：上游 14 项的稳定来源映射、每项观测/解决/保持办法、按项审核修复入口、当前用户计划任务 / LaunchAgent、5/15/60 分钟巡检、事件与 48 小时出口变化、批准的 Code 字段漂移恢复、三次恢复上限、失败/过期心跳、跨重启哈希撤销。后台不复用浏览器 ICE，不自动改变系统网络或时区。0.7 增加真实 OS 注册、重复自动执行与移除的冻结包 CI；权限、登录与休眠场景仍单独验收。详见 [逐项检测](CLAUDE_CHECKS.md)。

## 0.3：从检查结果到问题处理

已实现：基于官方排障资料的错误归因、正常 401 解释、代理 CONNECT 407、网络阶段 / TLS / 限流 / 服务错误、Code 代理与配置问题、直接处理入口、一站式确认方案、确定性配置修复、私有备份与撤销、修复后自动复检。主界面及 HTML / CLI 不再要求用户翻阅 JSON 自行判断。能力缺口、可选设置与实际故障分别解释，完整原始观测保留在脱敏导出中。

## 0.1：完整功能底座与日常工具

已实现：Windows / macOS 采集适配、五页极简桌面界面、14 类检查、系统与浏览器一键合并、IPv4/IPv6 独立策略、原生 STUN 校验、代理配置发现与连接诊断、50 次脱敏历史 / 比较、诊断包、偏好保存 / 恢复、事务式动态账号槽位与切换前重检。

完整保留原版 57 个源码文件及许可；固定适配器接入安装、修复、守护、路由迁移与维护核心更新，macOS 另外接入系统地区、代理客户端、临时浏览器和加密 DMG。这些操作是独立安装的原版功能，原版输出不构成独立测量。Windows 新增 CLI 安装位置与设备 / 字体信息，浏览器信息按需在本页生成。

发布门槛：完成来源与许可核对、桌面交互检查、Windows 包验证，并在说明中保留 DNS、路由关联与防火墙能力缺口。手机端与 Linux 不作为当前产品适配目标。

## 后续：故障场景与防护验证

在隔离虚拟机或明确选择的测试设备中，验证断线、网络切换、DNS 改变、睡眠恢复、IPv6 恢复和代理重启。观测网络层数据包，而非只看进程是否被终止。

Windows 防火墙/WFP 与 macOS pf 必须独立评估。任何保护功能都需要明确范围、恢复路径和抓包验收；常规“一键检测”继续只读，不能通过点检测按钮改动系统网络。

没有验证通过的防护模块不进入已支持能力清单。第一阶段没有“零泄漏”保证、账号安全评分或封禁风险预测。
