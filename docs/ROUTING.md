# 原生 Claude 路由配置

EnvScope 在“持续维护”提供 Clash Verge 路由方案；检测结果中的规则修复也使用同一实现。
Windows、macOS 使用同一份生成、事务与验证代码。测试不会改变开发机器的真实代理。

## 用户操作

1. 确认实际使用地区与目标，完成检测。代理客户端须已启动并处于规则模式。
2. 点击“读取可用代理组”，选择当前实际代理节点所在的组，再生成方案。
3. 阅读具体影响与 16 条规则，确认后创建私有备份、写入、重载并自动复检。
4. 需要撤销时点击“预览恢复原配置”。恢复完成后仍保留备份和事件日志。

仅修改已发现的 Clash Verge `profiles/Script.js` 和 `clash-verge.yaml`；
`profiles.yaml` 须明确登记全局 Script 项。多个资料目录、文件过大、无法确认节点、
非规则模式或其他代理客户端都转为具体手动步骤，不调用旧版统一修复替代本项。
控制接口仅使用配置中明确的本机 HTTP 地址或 macOS Unix socket，不扫描或猜测端口。

## 修改与验证范围

规则顺序为 3 条 UDP AND 规则（3478、5349、19302），随后 13 个域名后缀。
UDP 可按已确认目标走代理或拒绝；拒绝这些端口可能影响其他应用的语音 / 视频。
组名必须是配置内存在且实际选中代理节点的组。选择代理 UDP 时要求节点明确报告支持。

原有全局脚本保留，托管包装在原 `main` 返回后添加规则，不执行用户 JavaScript。
重复执行只替换唯一且完整的 EnvScope 托管块；唯一且完整的旧版 macOS
claude-switcher 托管块可迁移。无标记的用户内容与旧 Merge 规则不做猜测删除。
复杂脚本写法由客户端编辑器核对，不把静态拼接当作 Boa 引擎执行成功。

Clash Verge 的全局脚本由 GUI 生成配置时执行；仅调用内核重载不会重新执行它。
因此立即生效使用当前生成配置的 `rules` 字段，其余 YAML 值逐项保持不变，随后
要求 Mihomo 重载该完整文件。此操作可能短暂影响共享该代理的其他应用，也会载入
该文件已有的设置。加载后核对全部 16 条规则的顺序、目标、禁用状态及实际节点链。
下次 GUI 重新生成、切换订阅或更新后必须重新巡检；后续订阅扩展仍可能覆盖全局脚本。

通过只表示**本次内核运行配置**满足要求，不代表所有流量经过代理、地区资格改变、
账号认证成功，或后台永远不会漂移。全局模式仍可由检测核对，但本项不会自动改模式。

## 失败与恢复

预览不写入。方案绑定 90 秒内的报告、目标、配置字节、全局脚本登记、控制接口与
实际节点。确认时重新读取；变化则拒绝旧方案。只有布尔值 `true` 才允许执行。

原文件、目标文件及 SHA-256 在写入前保存到 `.envscope/routing/<事务号>/`，
先保存写入意图，再替换文件。每个文件使用同目录临时文件、fsync 与原子 rename；
这是可恢复的多文件事务，不宣称整个目录在断电时天然原子或跨文件系统原子。
进程退出后保留事务，阻止覆盖未完成记录；恢复需重新预览并明确确认。

加载 / 读回失败会尝试恢复原文件并重载。只有原规则和原节点链读回一致才标记恢复完成。
接口离线、权限不足、后续编辑或备份损坏保持“需要继续恢复”，保留所有材料，
不会为了显示成功覆盖用户的新修改。按日私有事件日志不写控制密钥或代理口令。

## 证据与来源

- `tests/test_routing.py`：只读预览、确认、外部编辑、循环 YAML、脚本组合、失败与中断恢复、选中检查原生分流；使用临时文件或 loopback。
- `scripts/routing_smoke.py`：Windows/macOS 界面模拟，验证预览、确认、自动复检、撤销及红色故障入口。
- `scripts/routing_core_smoke.py`：官方 Mihomo v1.19.33，固定校验和；关闭 TUN、DNS 和代理监听，仅临时控制接口。Windows 测 HTTP，两个 Mac 架构测 Unix socket。结果以对应 CI 运行证据为准。
- 冻结桌面测试覆盖 YAML 依赖打包和路由界面入口；真实 Clash Verge GUI 重生成、真实账号与流量场景仍需设备验收。
